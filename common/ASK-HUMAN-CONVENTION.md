# 人机提问沟通规范（Ask-Human Convention）

- 日期：2026-08-18
- 目的：流水线里任何 agent（Terra / 拆题 / 写手 / judge / operator）在中途停下来问人时，**用大白话、像会沟通的人那样问**，不报黑话日志、不把功课甩给人。
- 背景：human-vibe 研究早就吐槽过——agent 常满嘴术语、选项写成"实现方案"而非"后果"、不给上下文、让人替它做它本可自查的功课。本规范对齐 `phase2-paper/GATES.md`（结构门）与 `jean` 的两条铁律（决策不蒸发、不替人拍板）。
- 载体：DSH 的 `ask_user_question`（question / header / options / multi_select）。

## 1. 什么时候该问，什么时候不该问

**该问（轻分叉，三选一）**：
1. 真分叉且不可逆/昂贵（"用方案 A 还是 B"）；
2. 需要人的偏好或权威（"系数取多少""这步要不要保守"）；
3. 影响后续走向、AI 没有资格自己定的（方向、取舍、审美）。

**不该问（先自查，别甩给人）**：
- AI 能自己查证/推演/跑一下就知道的（先算完再问，带着结果问）；
- "可以吗 / 对吧 / 我继续了"式假确认（这是刷存在感，不是提问）；
- 需要人读一堆内部代号才能理解的（问之前先翻译成人话）。

## 2. 提问七条铁律

1. **结论先行（BLUF）**：第一句就是"需要你定：___"。不铺垫、不绕。
2. **大白话，术语降级**：技术词第一次出现必给一句人话。项目黑话对照（写手/拆题/judge 提问时照此翻译）：
   | 黑话 | 人话 |
   |---|---|
   | 补全度 G | 骨架的漏洞补全了没有 |
   | 严谨性 R | 每一步别人能不能照着查 |
   | 可读性 L | 读起来像不像人写的、累不累 |
   | 窄缝题 | 它"不会但给了提示就会"的那类题 |
   | blocker | 卡点（缺什么导致推不动） |
   | 六态 | 每句话标"已证 / 引用 / 悬着 / 卡住" |
   | 依赖树 | 哪个引理要先证、别的才站得住 |
   | G0/G1/G2/G3 门 | 拆题 / 每块 / 拼接 / 定稿 四处人验收 |
3. **一题一决定**：一个问卷只解决一个决定；多个决定拆成多个问题，别塞一坨。
4. **选项写"后果"不写"实现"**：
   - ❌ "用 confirm_policy=per-batch"
   - ✅ "B：每批互不依赖的引理一起审（省时间，但出问题要整批回看）"
5. **给推荐 + 理由**：默认把推荐项放第一并标 `(推荐)`，一句话说清为什么。
6. **给必要上下文，只给必要**：≤ 3 句背景；只放"不看会选错"的事实；附一句"已替你做的功课"（我查了 X、算了 Y）。
7. **留逃生口**：固定提供"跳过 / 换种问法 / 让我先看细节"。

## 3. 反模式（禁止）

- 黑话轰炸、用文件名/内部代号当问题主体；
- 连环追问（一次抛 N 个小窗）；
- 把决策责任伪装成问题推给人（其实该 AI 自己定）；
- 选项不互斥、不给推荐、不标后果；
- 问"是不是/好不好"这种没有信息量的二选一；
- 不问但擅自做不可逆动作（那是 `approval` 的事，不是问卷）。

## 4. 与结构门的关系（各司其职）

- **结构门 G0–G3** = 审**产物**（依赖树对不对、每块证明对不对、拼接连不连贯）——结构化、可批、可回溯，进账本；
- **本规范的问卷** = 轻**分叉**（哪条路、取什么值、要不要继续）——快、内联、临时；
- 问卷可以**嵌在门里**：如 G1 某块有 3 个疑点，先按本规范问"疑点 1 你要不要采纳这个修法（推荐）"，再进下一疑点。

## 5. 一个好问题的模板

```text
header: 选一个（这一步的修法）
question: 第 B3 块的证明有一个可选简化：把两个小引理合并成一个。
          【已替你做的功课】合并后总长度短约 1/4，且不改变依赖关系。
          需要你定：合并，还是保持两个分开？
options:
  - "合并（推荐）：更短、更好读，代价是单块稍大"
  - "保持分开：每块更小、更好单独核验"
  - "先跳过，我看看两版再定"
```

## 6. 落点

- `SPLITTER.md`、`GATES.md` 与各 agent 提示词在需要提问时，**必须遵守本规范**；
- 问卷的每个回答都进账本（决策不蒸发）：问题原文＋选项＋人选＋时间，落到 `runs/pretest/` 或 run 目录。
