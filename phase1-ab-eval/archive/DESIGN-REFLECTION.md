## 1. 为什么暂停：三个递进的反思

### R1. 任务本质是"证明补全/扩写"，不是"独立证明能力"

老师的任务：**根据一个不算很完整的证明思路，补充成完整证明**。

我们的题目包实际给写手的是：定理陈述 + 证明骨架（分步） + 允许依赖（关键引理，
如 P007 直接给 Cauchy–Binet 与 Möbius 反演）。数学的"难"已经被骨架和引理大幅消解，
写手被考的是：能不能读懂脚手架、把每一步跳跃展开成严谨推导、正确组合允许引理、
组织一条完整逻辑链。

结论：这测的是**证明写作/扩写能力**，不是"从零做数学"的能力。

### R2. 之前的 A/B 比较错位了

skill 提示词优化的目标（诚实性、依赖审计、缺口可见性）与"补全质量"不是一回事，
甚至冲突——"无法确认关键推理时停止硬补"这条规则，恰好教模型在补不齐时停下。

dev 数据的方向性证据（样本小，未达统计显著，但机制清楚）：

| 指标 | A（baseline） | B（skill） |
|---|---|---|
| acceptable（真补完了） | 8 | 5 |
| conditionally（诚实但没补完） | 4 | 8 |
| 数学正确性 C 的 mean_diff（B−A） | — | −0.13 |

更隐蔽的是评分权重本身也配错了：`weighted = 0.35·H + 0.25·D + 0.25·R + 0.15·C`。
诚实(H)的权重是正确性(C)的 2.3 倍——这是"审计模型失败"的指标，不是"测评扩写质量"
的指标。skill 提示词照着 H/D/R 设计，所以总分显得"不差"，但老师真正要的 C 在下降，
被权重稀释了。

### R3. 扩写能力的有效测评区间很窄

- 题目太简单（P007，两组全 4 分）：模型不靠骨架也会做，区分不出扩写能力 → 天花板。
- 题目太难（P011 A6，模型完全不会）：扩也扩不出，两组都躺平 → 地板。
- 有效区间 = **模型自己不太会、但给骨架＋关键引理后能补出来** 的窄带（P010 接近，
  但被题包 D1 bug 污染）。

这个窄带是 **model-relative**（相对模型能力边界的）难度，且会随模型版本漂移。
选题前必须先摸当前模型的能力边界，这对测评提出了很高要求。

## 3. 重启前必须重新定义的问题（仅记录，未派任何工作）

1. **测评对象**：从"诚实/依赖审计"改为"证明补全质量"。候选主指标：骨架 gap 的补全度、
   数学正确性、每步严谨性、可读性；诚实降为护栏（只在补不出来时起约束）。
2. **评分权重**：正确性/补全度回到主导，H 不再是 35% 主分。
3. **选题**：先做能力预测试，找"可扩写但不自会"的窄带题，避开天花板（P007 类）与
   地板（P011 A6 类）。
4. **骨架/依赖本身是变量**：给多少脚手架决定"扩写空间"大小，也是测评设计的一部分，
   不是固定背景。
5. **token 配置**：reasoning（思考）与输出需分开记账，或降 reasoning 档位，
   否则"补完证明"这种又要想又要写的任务会被思考吃光输出预算。
