§1.0 · 项目定位

研究问题：不是「能不能写」，是「流程是否更可审计」proof-expansion 的任务定义与成功标准（口径对齐）

任务：证明扩写

输入 = 定理陈述 ＋ 证明骨架 ＋ 允许依赖 ＋ 写作要求；
输出 = 结构完整、步骤可审阅、依赖可追踪的证明 ＋ 缺口记录。
不追求自动发现定理；模型输出永远不直接标记为 proved。

与纯「让 AI 写数学」的区别

  • 模型能力（推导、找引理）与流程能力（拆步、管依赖、报缺口）分开评测；
  • 核心主张：缺口诚实性——缺信息时报告，而不是编造。

预注册的成功标准

相对 Baseline 至少显著改善以下两项、且不损害正确性，流程才算有效：

  • 缺口识别与诚实报告
  • 证明步骤可审阅性
  • 假设与依赖的显式管理
  • 研究者风格的稳定控制
  • 研究者最终修订时间

只增加篇幅/模板/形式标记而无错误率与修订成本改善的，判无效——这条对今天的 Seidel 结果同样适用。

§2.1 · 本轮输入

Seidel 固定点 Floer–Hochschild 项目输入不是一道题，是一份「研究章程」——它规定了目标、门与账本

数学目标（三级阶梯，只声明证到的最强级）

COφ,δ,ε : HF*(φ; δ, ε) ⟶ HH*(A, 𝒫φ) 为拟同构

阶梯：① 全局单项独同构 ν（含 νk）→ ② 迭代可容许类 → ③ 一般自同构（需 φ-适应 stop 定理）。一份「全局 monodromy ＋ 可复用机器」的首篇论文即合格。

章程的四道阶段门

Ⅰ 定理与可行性审计 → Ⅱ 有界证明模块 → Ⅲ 独立盲审 → Ⅳ 成文。禁止一口气写论文；八条不可协商的数学承诺（有限阶结论、方差正确、识别 Seidel 真映射…）全程约束。

六态账本：每条断言必须带状态

FIXED 已定约定 IMPORTED-VERIFIED 已核文献 PROVED-IN-PROJECT 本项目证明
CONDITIONAL 有条件 CANDIDATE 候选构造 BLOCKED 精确阻塞

这是整个体系的基石：agent 不许把「看起来对」写成「已证」。有效状态按 worst(自身, 全部前置) 沿 DAG 传播——一个上游阻塞会诚实地污染整条下游链，包括 headline。

§2.3 · 这个形状意味着什么

DAG 的形状直接决定了流水线的策略

深而窄 ⇒ 并行无利可图

24 层串行深度、最宽 3，理论最优加速比仅 1.58×。结论：吞吐不是目标，每一步的正确性传播才是——错一块，污染半径最大的可达 36/38 个节点。

复用多 ⇒ 必须统一供给

25 个节点被 ≥2 个下游引用（引理复用）。任何一处「自己重推一遍」都是漂移风险 → 前置结论只允许来自上游块已落盘的原文，由调度器统一拼进任务书。

半径 top：N00/N01=36、N02=35 → 前 7 层全部 manual 人门（人工介入产出比最高的位置），深层批量放行。有限的人工时间用在结构性节点上。

§3.3 · 事故实录

四起事故，零一起靠 agent 自觉发现这是「闸门＞自律」最硬的证据

事故暴露方式沉淀
① 摘要降质：1423 行稿被「好心」摘要后喂编辑 agent → 7 页骨架稿，读起来完全像论文对照原稿发现细节全无逐字节输入契约；覆盖率机械断言；人不得在 agent 与资产间加中间层
② 子代理三连败：3 个块写手派发失败，主 agent 以同契约代写账本如实记录来源；产物照过同门幂等落盘＋「卡顿后先核对再重派」协议
③ 计数盲区：coverage 脚本只数 $…$ 漏 \(…\)守规矩的块写手主动报备触发排查，顺带抓出 1 例假回归双定界符计数＋负测试——闸门自己也要被测试
④ xref 断链：coordinator 产出 10 条交叉引用，组装器不消费，产出即丢弃架构审计归因发现消费协议＋引用 ∈ 依赖闭包否则拒装＋回归锁定
方法论：四条缝的关闭方式是同一个动作——把纪律从提示词层下沉到代码层。写在 prompt 里的纪律会漂移；跑在脚本里、被测试锁定的纪律不会。
