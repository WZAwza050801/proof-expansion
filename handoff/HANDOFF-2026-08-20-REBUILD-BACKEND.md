## 3. 为什么重构：后半段的三个缺口（本会话实证）

**事故经过**：学术编辑轮我（operator）把 1423 行拼接稿**先摘要再喂** agent，产出 7 页骨架
（陈述在、证明细节全无）。根因不是 agent 能力，是工作流后半段没有设计"成文编辑"环节：

| # | 缺口 | 实证 |
|---|---|---|
| ① | 编辑 agent 的**输入契约**未定义（DESIGN §4 只说"基于最简上下关系拼接"） | 喂摘要无人拦截 |
| ② | **语言/成文规范**缺字段 | "要英文"在整条链路上无处安放，直到 operator 临场补 |
| ③ | **产物完整性断言**缺失（splice.py 查符号/引用/重复，不查"内容被压缩"） | 7 页产物直接当成品 |

设计矛盾：DESIGN §5 自己论证了分块规避"长上下文注意力稀释"，前半段照此成功，
后半段却要求 6.5 万字符一次成型——**后半段违反了本工作流自己的核心论断**。

## 4. 重构方案（operator 已认可的方向，未冻结细节）

**前半段（splitter→scheduler→block_writer→账本）一行不动。** 后半段拆两步：

### 2a. 逐段成文（新增，N 个并行 agent；operator 倾向按里程碑切 8 段）
- 输入契约（硬）：该段全部块原文**逐字节**＋全局约定卡＋`language: English` 字段；
- 职责：英译＋定理环境＋段内衔接；**禁摘要、禁删证明**；
- 断言：产出长度 ≥ 输入 × 阈值（机械检查，阈值待定，建议 ≥0.8）；
- 段切分建议：P0(4块)/P1(3)/P2(7)/P3(5)/P4(5)/P5(2)/P6(3)/P7(9)。

### 2b. 机械组装＋终检（升级 splice.py 或新增小脚本，仍是确定性代码）
- `\newtheorem` 去重＋统一编号＋交叉引用；
- 引言/结论/目录（一次小派发，输入=8 个段标题＋账本统计）；
- **内容覆盖断言**：Σ段产出 vs `paper.md` 的公式/定理计数不得丢失；
- xelatex 编译门（绿灯配方：`ctexart+amsmath/amssymb/amsthm/amscd+xelatex`，
  已在 `RUN-LOG.md` 验证；英文版可退回 `amsart`）。

### 需要同时改的文档
- `DESIGN.md` §4：补"阶段 2a/2b"两小节＋三条缺口对应的硬规则；
- `splicer.md`：升级 v0.2——输入契约（逐字节）／语言字段／长度断言，旧提示词仅作历史参考；
- 新增机械检查脚本（内容覆盖断言），与 splice.py 的 lint 并列。

### 待 operator 决策的细节（下个会话开工前问一遍）
1. 段切分粒度（8 里程碑段 vs 更细）；
2. 长度阈值定多少（0.8 vs 0.6）；
3. 引言/结论是单独 agent 还是并入 2b 的人工模板；
4. 英文版编译用 `amsart` 还是保留 `ctexart`（纯英文后 ctex 非必需）。
