# 分块撰写与拼接：论文写作 Agent 的上下文控制设计

- 日期：2026-08-18（v2：新增"阶段 0 命题依赖树生成"，对齐研究者/老师的建议）
- 2026-08-20 v3：**重构阶段 2**。Seidel 预试实证原"整体处理拼接"设计有三个缺口（输入契约/语言字段/完整性断言），拆为 2a 逐段成文＋2b 机械组装。事故复盘见 `handoff/HANDOFF-2026-08-20-REBUILD-BACKEND.md` §3。
- 2026-08-20 v4（operator 定调）：2a 粒度改为**块级局部 LaTeX**（一块一 fragment＋块级编译探针）；新设**调度编辑 agent**（大 agent 只出装配指令、不出正文，硬规则④）。
- 状态：设计稿（论文写作 agent 的关键一环；与 `phase1-ab-eval/experiment-design.md` §1.0b 的"题目粒度 = 一个基本步骤"互为表里）
- 模板参照：桌面 `seidel_conjecture_distilled_work_charter.md`（P0–P7 脊柱＋completion test＋六态账本＋§7 写作纪律）

## 1. 一句话

长论文不放进一个上下文里写：**先把精简证明拆成"命题依赖树"，每个小引理用一个独立 agent 扩写，再按依赖树拓扑序整体处理拼接粘成论文**。一次性写成整篇会跳步、注意力稀释、上下文堆积——拆开写成本几乎不增，省的是上下文控制与质量。

## 1.5 总流程（老师建议的四步）

```
精简证明(类似 Seidel charter)
  └─► [阶段0] 生成命题依赖树（拆题）
        └─► [阶段1] 每个小引理一个独立 agent 扩写（逐块）
              └─► [阶段2a] 块级局部成文（一块一份局部 LaTeX；逐字节输入契约＋长度/覆盖断言＋编译探针）
                    └─► [阶段2b] 调度编辑（大 agent 只出装配指令，不出正文）＋机械组装＋终检（覆盖断言＋编译门）
                          └─► 完整论文
```

## 2. 阶段 0：生成命题依赖树（拆题，`phase2-paper/prompts/splitter.md`）

- 输入 = 精简证明（定理陈述 ＋ P0–P7 式脊柱，每步一个证明义务）。
- 输出 = **命题依赖树**（DAG）：节点 = 一个自足的小引理/命题；边 = 依赖（"引理 B 的证明用到引理 A 的结论"）。
- 每节点携带：`id`、自足命题陈述、依赖（前置节点）、允许依赖（外部定理）、扩写验收标准。
- 拆题规则：
  1. 节点要小到"一个 agent 在一个上下文里能完整、严谨地扩写"，大到"有独立意义、可单独核验"；
  2. 依赖只保留证明真正用到的（最简 DAG，不引入冗余边）；
  3. 全局约定卡（符号/记号/命名）随树一起产出，全树唯一；
  4. 拆题可用 agent 做（见 SPLITTER 提示词），但必须经人复核——树的形状直接决定论文结构质量。

## 3. 阶段 1：逐块扩写（每块四进三出）

输入（局部上下文，**不携带论文其余部分**）：

1. 全局约定卡（精简版，全块共用，保证符号一致）；
2. 前置结论摘要（"第 k 块已证：……"的引用句，六态 = PROVED-IN-PROJECT）；
3. 允许依赖（精确陈述，无名号无证明）；
4. 本块义务（objective ＋ completion test）。

输出：

1. 本块正文（自然写作；**不复述背景、不重复全局约定**——否则拼接后论文满是重复段）；
2. 结论声明（一句可被后块引用的"已证结论"＋六态）；
3. 依赖与未决标注（引用了哪些前置块/允许依赖；若有 blocker：最小 blocker＋最强已证定理）。

## 4. 阶段 2：成文与组装（2a 块级局部成文 ＋ 2b 调度编辑与机械组装）

> **v3 重构依据**：原设计"整体处理拼接"在 Seidel 预试中被证伪——1423 行机拼稿一次喂给编辑
> agent，产出 7 页降质稿（定理陈述都在，证明细节全无）。§5 论证的分块规避长上下文稀释，
> 同样适用于成文层：**后半段不得要求全文一次成型，这是本工作流自己的核心论断。**
> **v4 定调**（operator）：粗扩写之后**不直接合并**——每块先成文为一份局部 LaTeX，再由调度
> 编辑 agent（只管编号/引用/衔接等论文级事务，不碰数学）统一定调，机械代码组装。

### 4.0 四条硬规则（实证缺口 → 管线级规则，违反 = 事故）

| # | 规则 | 实证来源 |
|---|---|---|
| ① | **输入契约逐字节物化**：成文 agent 的输入必须含该块原文，落盘物化后再发送；operator 不得在 agent 与资产之间加任何"贴心"中间层（摘要/缩写/改写） | Seidel 编辑轮：operator 先摘要再喂，7 页骨架被直接当成品记档 |
| ② | **成文参数显式字段化**：`language` 等参数是任务书字段，不是临场口头补充；链路上任何一环不得"默认"它 | "要英文"在整条链路上无处安放，直到 operator 临场补 |
| ③ | **产物完整性断言机械化**：每块产出必须过确定性断言（`coverage_check.py`），不信任任何"我确认没丢内容"的口头保证 | 7 页产物读起来完全像论文；splice.py 只查符号/引用/重复，不查"内容被压缩" |
| ④ | **输出义务局部性**：任何 agent 的产出义务不得包含论文全文；需要全局视角的角色（调度编辑）只产出装配指令（JSON＋短句清单），论文正文由确定性代码组装 | 事故的本质＝编辑 agent 的输出义务覆盖全文；①③堵输入侧与事后检查，本规则从源头堵输出侧 |

### 4.1 阶段 2a：块级局部成文（每块一个可并行小 agent，`phase2-paper/prompts/splicer.md` v0.3）

- **粒度**：**一块 → 一份局部 LaTeX fragment**（Seidel：38 份）。段（P0–P7 里程碑）仍是论文节界，但只作为分组元数据传入，不再作为成文的上下文单位。
- **输入契约（硬，缺一拒作）**：
  1. 该块原文（【正文】＋【结论】）**逐字节**；
  2. 全局约定卡；
  3. 成文参数：`language: English|Chinese`、`docclass: amsart`、本块 label 前缀（如 `eq:N07-`）、前块结论行（一句话，供块首衔接）。
- **职责**：英译、amsthm 定理环境化＋`\label`、块首一行衔接（据前块结论行，不复述数学）、符号遵约定卡；六态标注逐个保留。
- **禁止**：摘要、压缩、删除任何证明步骤/计算/反例讨论；重证、改结论、发明或合并引理、越约定卡改符号。
- **断言（过门条件，G2a）**：
  1. `coverage_check.py segment`（对该块）——长度比 ≥0.8 ＋ 公式/定理环境/六态标注计数不降；
  2. **编译探针**：fragment 套 `tools/fragment_wrapper.tex` 跑 xelatex，0 errors 才过——LaTeX 纪律错误在块级拦截，不许攒到组装后（Seidel 教训：216 处 text-mode `_` 拼接后才发现）。

### 4.2 阶段 2b：调度编辑（大 agent，只出指令不出正文）＋ 机械组装＋终检

- **调度编辑 agent（`phase2-paper/prompts/coordinator.md`）**——流水线唯一有全局视角的角色，因此被规则④锁死：
  - 输入全部为小体量元数据：段结构、节点元数据（id/标题/命题类型/有效六态/label/字数）、每块【结论】行（一句话×38）、账本统计、成文参数；
  - **禁读任何块【正文】，禁输出论文正文**；产出 = 装配指令 JSON（节序、编号策略、label→编号映射、跨块引用解析、节间衔接句、引言/结论大纲、小编辑清单、问题清单）；
  - 引言/结论正文由一次小派发生成（输入＝大纲＋账本统计，仍不接触证明正文），或人工模板。
- **机械组装（`assemble.py`：消费 fragments＋装配指令 → `paper.tex`）**：`\newtheorem` 去重、统一编号与交叉引用、文本模式 `_` 转义、amscd 补齐（Seidel 已实证清单）；**xrefs 消费**（2026-08-21 补，此前字段被静默丢弃：新 `find/replace` 协议要求短语恰好出现一次，旧协议自动短语定位）；**`\Nref{NXX}` 解析**（splicer v0.4 语义宏→按 labels 全表渲染 `Theorem~\ref`）；**bibliography 渲染**（条目文本来自 DOSSIERS 汇编，coordinator v0.2 职责 7——此前参考文献表在流水线中无工位）。
- **内容覆盖断言**：`coverage_check.py paper`——Σ fragments vs 机拼基准（`paper.md`）的公式/定理计数不得丢失。
- **编译门**：英文版 `amsart + amsmath/amssymb/amsthm/amscd + xelatex`（纯英文后 ctex 非必需；中文回退绿灯配方 `ctexart` 同套宏包）；exit=0 且 0 errors 才过 G2。

### 4.3 确定性检查清单（原 v2 §4，职责移入 S2）

1. 拓扑序无环、拼接顺序合法；
2. 符号一致性：同一符号在任意两块同义（约定卡为唯一权威）；
3. 引用完整性：每块的"依赖"都能对上前置块结论或允许依赖（无孤儿断言）；
4. 结论链闭合：头号块的结论 = 论文头号定理，无悬空义务；
5. 重复检测：块间大段相同文本（背景复述）报警并交由拼接器删除；
6. **全局 claim 账本**（六态）作为跨块状态：账本就是块与块之间的"接口状态"。

### 4.4 operator 四步分解（S1–S4，权威口径，2026-08-20 定）

| 步 | operator 口径 | 落到组件 | 过门 |
|---|---|---|---|
| **S1** 把每段写成 latex | 2a 块级 fragment（`splicer.md` v0.3；段＝分组元数据） | G2a：`coverage_check.py`＋编译探针 |
| **S2** 串起来，符合命题图逻辑，角标前后恰当 | `coordinator.md` 装配指令＋`splice.py` 组装＋§4.3 六项检查 | G2b-1：指令合法（拓扑序/引用闭合/label 映射一致） |
| **S3** 论文级格式审查、调整、输出 | 机械格式化（组装后处理）＋**格式审查报告**（清单制：只出清单不出正文；确定性编辑机械执行，涉内容的按清单路由回 S1 对应块） | G2b-2：报告零未决项 |
| **S4** 编译审查、交付 | xelatex 门（exit=0 且 0 errors）＋交付包 | G2（人确认） |
| **S5** 论文级审查轮（审成品，2026-08-21 设立） | 三件套：**G3a** `tools/paper_lint.py` 刚性自洽（E1–E7/W1–W5，零 LLM）→ **G3b** 节级内容审查（`prompts/paper-reviewer.md`，一节一 agent 并行，只出 FINDING 清单）→ **G3c** 全局对账（引言/结论承诺 vs 机械事实，不读全文） | G3：G3a 零 error＋G3b/G3c 零未决项；处置路由同 S3（机械修/回块/questions） |

- **S3 与规则④的相容性**：格式审查者的产物是**报告**（编辑清单），不是论文正文——输出义务仍局部；涉数学内容的修改一律回块，不许在论文级直接改写。
- **S4 交付包（固定清单，缺一不算交付）**：`paper.tex`＋`paper.pdf`；coverage 报告（块级＋全文两份）；装配指令 JSON；编辑与问题两本账；六态账本快照；编译日志；**参考文献表**（`thebibliography`，条目与 DOSSIERS 逐条一致）；**lint 报告**（S5/G3a）。
- **S5 设立依据（2026-08-21 operator 定调"审成品是重要技能块，从零做，插入工作流"）**：机械闸门审结构、盲审（块级）审孤立块、S3 裁决格式决定——**拼装后的整篇**（跨节一致性、承诺-兑现对账、arXiv 自洽标准）此前无工位。实证：paper-v3 首跑 lint 即抓出引言统计失真（声称 244 vs 实际 479）、133/170 label 无引用者、参考文献 8/9 列而未引、overfull>10pt 53 处（最大 238pt）。S5 = paper_lint（刚性）＋节级审查（内容）＋全局对账（账目）三件套；契约见 `prompts/paper-reviewer.md`；模型走 preset `role-paper-reviewer`（micu/gpt-5.6-sol）。
- **状态词表单源（P0 试跑实证）**：块内实际使用 8 个状态——六态（FIXED/PROVED/CONDITIONAL/CANDIDATE/BLOCKED/UNVERIFIED）＋变体 PROVED-IN-PROJECT（12 处）与 IMPORTED-VERIFIED（11 处）；形态两种（`\tag{X}` 13 处＋圆括号 462 处）。各提示词与断言器以此为准；`coverage_check.py` 已改为词表无关计数（任意 `\tag{...}`/`[STATUS: ...]`），不会因变体漏数——新变体仍会不断出现，词表只作记录不作闸门。

### 4.5 与 gates 的关系

G2 拆两个机械前置：**G2a**（＝S1 过门：每块成文断言＋编译探针通过）＋ **G2b**（＝S2/S3 过门：装配指令合法、组装编译全绿），人工确认仍在 G2 终点；确认模式与污染半径的取严合成不变（见 `GATES.md` §2.1）。

## 5. 为什么成本几乎不增（本设计的核心论断）

- **单次生成**：总产出 token ≈ 一次写完（分块常更省：局部上下文不诱发无关内容）；单次调用窗口小，规避截断与长上下文注意力稀释（lost-in-the-middle）。
- **多轮迭代写作**（草稿→修改，agent 的常态）：单一大上下文每轮重读整个前缀，O(n²)；分块每轮只重读本块，O(n)——**实打实省 token**。
- **并行**：DAG 中互不依赖的块可并行撰写，墙钟时间大幅下降，总 token 不变。
- 额外开销只有：块接口的少量重复（约定卡/前置摘要）＋拼接检查——与正文规模相比可忽略。

## 6. 与测评实验的关系（变量不混淆）

- **块级 = 现有测评单元**：一个题包 = 一个依赖树节点；A/B 提示词对比在块级做（G/R/L/C + 失败模式）。B 提示词中的"不复述背景、引用前置结论、六态标注、最小 blocker"正是分块写作所需的块接口纪律。
- **拆题级 / 拼接级 = 两条另评的评价轴**：依赖树质量（拆题）与拼接质量（整体处理）都用确定性检查＋一次全局 judge 读，**不得混进块级 A/B 分数**——否则"提示词""拆题器""拼接器"三个变量混淆。
- 论文写作 agent 的完整形态 = **生成依赖树（拆题，SPLITTER）→ 逐块扩写（A/B 写手）→ 块级局部成文（`phase2-paper/prompts/splicer.md` v0.3）＋ `coverage_check.py` 断言＋编译探针 → 调度编辑（`phase2-paper/prompts/coordinator.md`，只出装配指令不出正文）→ 机械组装（`splice.py`）＋编译门 → 全局审读**。本仓库当前实验负责"逐块扩写"这一环的提示词优化；拆题、成文与组装已配齐规范与代码。
